## What failed first

1. **REST PATCH `/pulls/{n} -f draft=true` — silent no-op.** HTTP 200, draft stays false on subsequent GET. The forward-direction sibling-field unlock (`-f draft=false -f draft_message=ready` per `pr-triage-and-next-steps` skill) has no reverse; verified by trying 4 siblings + the `/issues/{n}` PATCH endpoint. Do NOT spend more time on this — go straight to GraphQL.
2. **GraphQL `convertPullRequestToDraft` — blocked by `remaining=0`.** Per-hour reset window. Probe before bulk batches via:
   ```bash
   gh api graphql -f 'query={rateLimit{limit remaining resetAt}}'
   ```
3. **Org search via `gh search/issues` with paginate — rate-limited mid-run.** Symptom: returned a 403 body that looked like a search hit, polluting the result set. Switched to per-repo `repos/{O}/{R}/pulls?state=open` with explicit pagination — clean.

## Preview/dry-run gate (don't skip)

Before the bulk flip, post a preview to the originating thread showing: (a) total candidate count; (b) exception list (what will NOT flip and why); (c) per-repo counts; (d) sample PR(s) per repo. The flip should ONLY proceed after the user sees the preview and approves via free-text "go" or similar. The no-pick-one-menus anti-pattern does not apply here — the user already said "yes do it" + "keep going get it working" before scope was known; the preview is the exception-list gate, not a clarification menu.

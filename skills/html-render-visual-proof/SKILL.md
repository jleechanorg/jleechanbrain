# html-render-visual-proof

For HTML-output-only fixes (no JS, no UI surface change, no auth-gated route), the canonical `wa-visual-proof-playwright` recipe (start full Flask server, navigate browser, swap bytes, restart) is overkill. The HTML is generated by a single Python function — call it directly, serve the result via a one-route shim, screenshot.

This pattern is **strictly faster** (no gunicorn startup, no Firebase auth bypass) and **just as rigorous** (same Playwright viewport, same `vision_analyze` verification step, same evidence directory layout).

## When to use

- Server-side render function returns HTML (`render_*_page(payload, token)`, `render_landing`, `render_email_body`, etc.)
- Jinja / Mako template change
- OG card / share-card / preview snippet change
- Email template change

## When NOT to use (use `wa-visual-proof-playwright` instead)

- Touches `mvp_site/frontend_v1/**` (JS / JSX / CSS that runs in the browser)
- Wizard or campaign-creation flow with multiple steps
- Anything requiring Firebase auth bypass or the full Flask startup

## The 3-step recipe

### Step 1 — Render HTML directly via the Python function

```bash
# From the worktree root (or any path with the venv active):
/path/to/venv/bin/python <<'PY'
import sys; sys.path.insert(0, '.')
# Wipe stale cached module so a prior test invocation doesn't mask changes:
for m in list(sys.modules):
    if m.startswith('mvp_site.'):
        del sys.modules[m]

from mvp_site import render_module as m  # e.g. share_token

payload = {
    # Same shape as production observed via the public endpoint.
    # Get this from `curl -fsSL https://<prod-url>/api/shared/<token>` first
    # so the BEFORE/AFTER captures are against the EXACT data users see.
    'title': '...',
    'setting': '...',
    'description': '...',
}

html, status = m.render(payload, 'fake-token')  # or whatever signature
with open('/tmp/after.html', 'w') as f:
    f.write(html)
print('len:', len(html), '| status:', status)
PY
```

For BEFORE, either:
- `git show origin/main:path/to/render_module.py > /tmp/main_module.py` and `import /tmp/main_module.py` (ugly — module-load order is fragile), OR
- **Easier:** monkey-patch the decode helper or template path to a no-op, then re-run. E.g. if the fix adds a `_decode_embedded_unicode_escapes()` helper, monkey-patch it to a passthrough BEFORE rendering:

```python
import mvp_site.render_module as m
m._decode_embedded_unicode_escapes = lambda v: v  # simulate pre-fix
```

This produces byte-for-byte the pre-fix HTML without touching the worktree.

### Step 2 — Serve both HTMLs via a tiny shim

```python
# Use a port you KNOW is free (lsof -i :PORT first). 8765 is often taken.
# Bind 127.0.0.1 only — never 0.0.0.0.
import http.server, socketserver
PORT = 9876

class H(http.server.SimpleHTTPRequestHandler):
    def do_GET(self):
        path = self.path.split('?')[0]
        if path == '/before':
            body = open('/tmp/before.html', 'rb').read()
        elif path == '/after':
            body = open('/tmp/after.html', 'rb').read()
        else:
            self.send_response(404); self.end_headers(); return
        self.send_response(200)
        self.send_header('Content-Type', 'text/html; charset=utf-8')
        self.send_header('Content-Length', str(len(body)))
        self.end_headers()
        self.wfile.write(body)
    def log_message(self, *args): pass  # silence access logs

socketserver.TCPServer.allow_reuse_address = True
socketserver.TCPServer(('127.0.0.1', PORT), H).serve_forever()
```

### Step 3 — Capture both PNGs and vision-verify

```python
from playwright.sync_api import sync_playwright

URLS = [
    ('http://127.0.0.1:9876/before', '/tmp/share_landing_before.png'),
    ('http://127.0.0.1:9876/after',  '/tmp/share_landing_after.png'),
]

with sync_playwright() as p:
    browser = p.chromium.launch(headless=True)
    for url, path in URLS:
        ctx = browser.new_context(viewport={'width': 1400, 'height': 900})
        page = ctx.new_page()
        page.goto(url, wait_until='domcontentloaded')
        page.wait_for_timeout(300)
        page.screenshot(path=path, full_page=True)
        ctx.close()
    browser.close()
```

Then `vision_analyze(image_url=path, question="Quote the EXACT text in the highlighted blockquote box — character by character. Is there a literal backslash-u-2-0-1-9 sequence OR a real curly apostrophe?")`.


## Pitfalls

- **Catching this skill late wastes a turn.** When the user says "show me before/after screenshots" or "the prod preview looks broken" about a UI fix, load this (or `wa-visual-proof-playwright`) BEFORE writing the PR description. Proof first, PR text second.
- **Module cache.** `from mvp_site import render_module` inside an `execute_code` may pick up a stale cached version if the worktree was edited mid-session. `del sys.modules` for the package prefix before import.
- **Port conflicts.** 8765 is often taken by a uvicorn preview proxy. `lsof -i :PORT` first; pick something high (9876+) and unused.
- **Bind to 127.0.0.1, not 0.0.0.0.** Local-only evidence capture is fine; don't expose a render-shim socket to LAN.
- **Production URLs as evidence are not a substitute.** The user said "s5 still looks malformed" because they could see the prod URL was unfixed — that's the SIGNAL to capture LOCAL proof, not to wait for the preview deploy to finish.
- **The shim serves raw HTML, not the live server.** That means CSP headers / `<meta>` tags render in browser context correctly, but server-side session cookies / auth redirects don't apply. Fine for static-render fixes; NOT fine for wizard flows.
- **Vision prompt must ask for the literal escape vs. real character.** `vision_analyze` will describe both as "apostrophe" unless the prompt specifically asks it to distinguish literal `\u2019` from real `'` (U+2019).
- **Don't include the `MEDIA:/abs/path` Slack convention** when posting BEFORE/AFTER PNGs as Slack attachments — Slack renders the path as literal text. Use the `files.getUploadURLExternal` 3-stage recipe (`~/.smartclaw/skills/evidence-attach-to-slack/SKILL.md`) or just inline the markdown image link.
- **CSS `position: fixed` inside a transformed ancestor pins to that ancestor, not the viewport.** When revealing an element for screenshot capture, both `opacity: 0` AND `transform: translateY(...)` on the parent must be overridden, AND the element must be reparented to `document.body` (or any non-transformed ancestor) so `position: fixed` works against the viewport. Without the reparent, the floating element is positioned relative to the transformed containing block — verified 2026-08-19 PR #9134 (`#game-view` is the transformed ancestor; the mode-radio group had to be `document.body.appendChild(...)` to render correctly).
- **Playwright Node module lives at `/opt/homebrew/lib/node_modules/@playwright/mcp/node_modules/playwright/index.js`**, NOT at `~/.local/orch-venv/lib/...` (that's a Python pip package — imports pydantic instead of playwright-core). Verified 2026-08-19.
- **`page.evaluate(fn, arg)` takes ONE argument.** Passing multiple positional args silently drops the extras. Use a single object: `page.evaluate((data) => { ... }, { x: 1, y: 2 })`. Verified 2026-08-19.
- **Submit handlers with `currentCampaignId === null` short-circuit.** The `#interaction-form` submit at `app.js:5447` returns at `if (!userInput || !currentCampaignId) return;` when no campaign is loaded — `currentCampaignId` is module-scope `let`, not on `window`. Without a real auth flow, you cannot reach the patched block via submit. Mirror the patch logic from `page.evaluate` instead, AND keep a contract test that asserts the patch is in source.
